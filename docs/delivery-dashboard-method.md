# 自动化管理看板 · 搭建方法（以 Agenova 为实例）

> 目的：让交付状态自己说话——不用开会问人，打开一页就知道哪里堵了、堵了多久、上周有没有变好。
> 本文档是 2026-11-08 晚给 wunderforge/agenova 搭第一版看板时的做法记录，可复刻到任何用 GitHub / Jira 管票的项目。

---

## 0. 先想清楚：看板不是图，是对账工具

- 看板上的每个数字都必须能对回一个源头页面（哪列、哪张票、哪次运行）。对不回源头的数字不许上板。
- 统计口径先对齐再画图。实例：Actions 页总数 696 是两个工作流合计，CI 自己的编号是 #665，EKS 发布是 #25——口径不分清，图画得越漂亮错得越离谱。
- 看板只服务一个动作：**指出异常、逼出处理**。没有红线阈值的指标只是装饰。

## 1. 第一步：定指标（少而硬，一共五类）

| 指标 | 回答什么问题 | 红线（示例） |
|---|---|---|
| 各列票数（Backlog / Ready / In progress / In review / Blocked / Done） | 活堵在哪一段 | Done 连续一周为 0 = 报警 |
| 在制品数量（In progress） | 同时开了多少条线 | 小团队上限 4，超了先收尾再开新工 |
| PR 待审清单 + 每张年龄 | 代码单子卡了多久 | 超 14 天标黄、超 30 天标红 |
| 吞吐量（每周关票数、合并 PR 数） | 出货速度在变快还是变慢 | 连续两周下降要查因 |
| CI 健康（最近运行结果） | 自动检查还活着吗 | 主线或发布流最新一次失败 = 红灯 |

原则：指标宁少勿多。五类看全了，团队的交付健康就没死角；二十个指标没人看，等于没有。

## 2. 第二步：找数据源（每个指标标注来源）

Agenova 实例的数据源分两类：

**免登录的公开数据**（仓库是公开的，直接读页面）：
- PR 列表页：`github.com/wunderforge/agenova/pulls` —— 待审数量、每张的开启日期（算年龄）、作者
- Actions 页：`github.com/wunderforge/agenova/actions` —— 总运行数、各工作流最新编号与结果（绿勾/红叉）
- Issue 页：Epic 进度（如 E7 的 2/4）

**需要登录的数据**：
- 项目看板（Projects 的 Delivery Board 视图）：各列票数、各列成员票。个人名下的 Projects 看板未登录返回 404，必须用账号登录后读。
- 经验：登录名要用 GitHub **用户名**核对，邮箱+密码对不上时先查用户名，不要反复试密码（会触发锁定）。

复刻到 Jira 项目时一一对应：列计数 → Jira board 各列；PR 年龄 → 待评审单据列表；吞吐 → 每周 Done 的 issue 数；CI → 流水线最近运行。

## 3. 第三步：采集 + 快照（趋势靠攒，不靠记）

- 每次采集，先把当次的原始数字存成一份**带日期的快照**（本项目存 `snapshots.json`），再去更新展示页。
- 为什么：单次数字只能看现状，**增量要靠两次快照相减**。第一周看板上只有一个点，第四周才有趋势线——这是所有看板的必经之路，别指望第一天就画出曲线。
- 快照只存事实（日期 + 各指标原值），不存结论。结论每周重算，口径变了能回溯。

## 4. 第四步：展示层（一页，先异常后正常）

版面顺序是设计出来的，不是随手排的：

1. **顶部 KPI 瓷砖**：总票数、在制品、待审 PR、最老 PR 年龄、CI 状态——5 秒看完健康度
2. **红灯区**：超龄 PR、被堵的票、状态假账（票已关但状态还写着进行中）——异常永远排在正常前面
3. **各列分布**：七列计数一字排开，哪段淤积自己跳出来
4. **明细表**：在制品清单、待审 PR 清单（带年龄），点名到票，不许只给总数

## 5. 第五步：自动化（每周对账一次）

一条定时流水线，每周一上午自动跑（北京时间约 09:30）：

1. 按第 2 步的数据源重新拉一遍数
2. 和上周快照做差：哪列涨了、哪张 PR 又老了一周、Done 动了没有
3. 把新快照存档，重建展示页
4. 给负责人发**一句话增量摘要**（只报变化和红灯，没变化就不打扰）

人工从此只做一件事：看红灯、做处理。拉数、算账、画图全部交给流水线。

## 6. 第六步：用看板开会（这一步才是管理的本体）

- 周会只过红灯项，绿灯不念——念进度是浪费全员时间
- 每条红灯当场定性：审掉、拆小、关掉标 superseded，三选一，必须落一个
- 下周看板就是上周承诺的验收单：数字没动，说明承诺没兑现，对着板子说话，不对着人发火

## 附 B：复刻清单（换任何项目，只改三处）

1. 仓库/项目地址（数据源 URL）
2. 列名映射（对方项目的列叫什么，对到 Backlog/Ready/Doing/Review/Blocked/Done 六个语义位）
3. 红线阈值（按团队人数调 WIP 上限，按节奏调 PR 标红天数）

其余全部照抄：指标五类、快照机制、版面顺序、周更流水线、红灯开会法。

## 附 C：常见坑（这次全踩过或差点踩过）

- **状态假账**：票关了、状态没跟上 → 看板说谎。对策：每周采集时交叉核对 issue 状态 vs 项目状态，不一致的直接进红灯区点名。
- **总数对不平**：不同页面的统计口径不同（696 vs 665+25）。对策：每个数字在快照里注明来源页面和口径。
- **第一周没有趋势**：正常。别为了好看编历史数据，从基线开始攒。
- **看板变成新的汇报材料**：有人开始为了让数字好看而刷票。对策：红线只对事不对人，关票标 superseded 是正常操作不是认错。
