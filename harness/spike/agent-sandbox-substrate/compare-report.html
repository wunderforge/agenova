Warm pool vs cold start

A pre-warmed SandboxWarmPool makes a claim Ready in about zero seconds regardless of image size. Without one, the claim pays for the image pull inline — and that cost grows with the image.

01  The measurement

reproduce.sh compare runs each image twice. In the cold path a SandboxClaim references only sandboxTemplateRef — the controller provisions a fresh Sandbox and pod on demand, so claim → Ready includes the image pull, pod create, and container start. In the warm path a SandboxWarmPool with replicas: 1 is brought up first — it absorbs the pull — and then a warmpool:-backed claim adopts the already-running pod.

Each image is evicted from the node's containerd cache (crictl rmi) before its cold run, so the cold number reflects a real pull rather than a cache hit.

02  Findings

Cold-start time tracks image size

Cold claim → Ready rose 6s → 10s → 13s as the image grew ~4 MB → ~130 MB → ~250 MB — the pull dominates. The warm-pool path stayed at ~0s because that pull is paid once, up front, while the pool pre-warms. On kind with a fast registry path the absolute cold numbers are modest; on a slower network or with larger images the gap widens.

Deleting a warm-pool claim doesn't drain the pool

On v0.4.6, deleting a warm-pool-backed SandboxClaim terminates the claimed pod, but the SandboxWarmPool immediately provisions a replacement to hold spec.replicas — so the namespace pod count settles back to replicas, not zero. Only deleting the claim and the pool and the template drives it to zero. A cold-start claim (no pool) instead deletes its Sandbox and pod outright. The harness teardown phase deletes all three and asserts the pod count reaches zero.

03  Read with care

  • Single run per cell, not averaged; 1 s poll resolution. Small values (busybox) are order-of-magnitude, not precise.
  • kind is a single-node cluster with a fast local image path — absolute pull times are optimistic versus a remote multi-node cluster.
  • The warm-pool figure is measured after the pool pod reached Running; it excludes pre-warm time, which is where the pull cost moves to.
  • Image sizes are approximate published compressed sizes for context, not measured layer bytes.
