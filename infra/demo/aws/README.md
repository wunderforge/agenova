# Disposable Sydney EKS demo

External infrastructure prerequisite for [E13 #175](https://github.com/wunderforge/agenova/issues/175).
This does not install Agenova or prove Bedrock inference. Task and design: [packet](../../../work/0175-aws-demo-bootstrap/task.md).

## Resources and boundaries

Sydney only; dedicated VPC with two public subnets, no NAT gateway or load balancer;
standard-support EKS control plane; one On-Demand t3.medium AL2023 node with a 20 GiB encrypted gp3 root volume;
two immutable-tag ECR repositories; seven-day control-plane log retention; account-wide monthly cost alerts.
The explicit operator receives Kubernetes cluster administration, not AWS account administration.
No inbound SSH or public application service is configured. Worker node role has EKS/ECR/CNI permissions,
not Bedrock permissions. IMDSv2 is required with hop limit one; this is not proof of hostile-worker isolation.
Do not run untrusted workloads before E15 validation. The CNI currently uses the node role.

The API has a private endpoint and a public endpoint restricted to operator CIDRs.
No IAM user password/access key or root credential is generated by Terraform.
Use an existing non-root operator session. Application authentication and gateway-specific identity remain E14 work.

## Cost and lifetime

Owner budget: **AUD 100/month**, disposable usage. AWS Budgets uses USD here:
USD 50 is a conservative alert threshold, not a currency conversion guarantee or spending cap.
Verify current AUD/USD conversion, GST, account-wide spend and credits before each deployment.

Standard EKS control plane costs USD 0.10/hour (~USD 73 for 730 hours), before workers,
EBS, public IPv4, logs, storage/transfer and Bedrock. On 2026-09-28, AWS Pricing API
returned Sydney Linux t3.medium at USD 0.0528/hour and gp3 at USD 0.096/GB-month.
With one public IPv4 at USD 0.005/hour and 20 GB gp3, ten hours is approximately
USD 1.60 before creation/deletion time, logs, transfer, ECR, taxes and exchange rates.
The current authorized session lasts ten hours after readiness; see the task handoff for its deadline.
Sources: [EKS pricing](https://aws.amazon.com/eks/pricing/),
[EC2 pricing](https://aws.amazon.com/ec2/pricing/on-demand/),
[VPC IPv4 pricing](https://aws.amazon.com/vpc/pricing/).

`expires_at` is only a visible tag/output, **not automatic teardown**.
Schedule a cleanup owner and deadline before apply. Scaling workers down does not stop EKS control-plane billing.
Alerts are delayed and do not cap spending. For initial setup, use a short same-day session and destroy after validation.

## Prepare and validate

Install Terraform >= 1.9 and AWS CLI v2; use a non-root, preferably temporary login.
Never send credentials in chat or commit them. If using browser-based AWS CLI login,
verify provider credential compatibility before plan; do not copy tokens to tfvars.

From repository root:

```sh
export AWS_PROFILE=agenova-demo
aws sts get-caller-identity
aws eks describe-cluster-versions --region ap-southeast-2
cp infra/demo/aws/terraform.tfvars.example infra/demo/aws/terraform.tfvars
chmod 600 infra/demo/aws/terraform.tfvars
terraform -chdir=infra/demo/aws init
terraform -chdir=infra/demo/aws fmt -check
terraform -chdir=infra/demo/aws validate
```

Edit the ignored tfvars with the verified account, existing operator IAM ARN, current public
IP `/32`, notification recipient and new UTC cleanup deadline. Check 1.35 standard support,
Agent Sandbox compatibility, EC2 quotas and instance availability. Never add `0.0.0.0/0` API access.

The default backend is local. Restrict state/plan permissions using `umask 077`.
Retain state securely until all resources are removed. Only one operator may apply;
configure a shared encrypted state backend before team members independently use this stack.
State, tfvars and saved plans are ignored by git; the provider lock file must be committed.

## Plan and apply

```sh
umask 077
terraform -chdir=infra/demo/aws plan -out=demo.tfplan
terraform -chdir=infra/demo/aws show -no-color demo.tfplan
# Check account, IAM changes, CIDRs, resource counts, lifetime and cost before applying.
terraform -chdir=infra/demo/aws apply demo.tfplan
aws eks describe-cluster --region ap-southeast-2 --name agenova-demo --query 'cluster.status'
aws eks update-kubeconfig --region ap-southeast-2 --name agenova-demo --alias agenova-demo --kubeconfig "$HOME/.kube/agenova-demo"
KUBECONFIG="$HOME/.kube/agenova-demo" kubectl --context agenova-demo get nodes -o wide
```

Use explicit Kubernetes contexts for subsequent commands. Capture sanitized resource/status evidence.
An ACTIVE cluster is insufficient until the node is Ready. Agent Sandbox installation and Agenova/Bedrock
acceptance remain separate work; do not declare E13 complete from these outputs.

## Cleanup

First remove application-created load balancers, persistent volumes and other resources not owned by this stack.
Preserve required evidence/artifacts. ECR repositories deliberately refuse deletion while nonempty:
review and explicitly delete only disposable demo images, or retain those repositories through a reviewed plan.
Do not enable force-delete to bypass that decision.

```sh
umask 077
terraform -chdir=infra/demo/aws plan -destroy -out=destroy.tfplan
terraform -chdir=infra/demo/aws show -no-color destroy.tfplan
terraform -chdir=infra/demo/aws apply destroy.tfplan
terraform -chdir=infra/demo/aws state list
aws eks list-clusters --region ap-southeast-2
```

Check tagged EC2 instances, EBS volumes, public addresses, network interfaces, ECR and logs for leftovers.
Do not delete unrelated team resources. Destroy also removes this stack's budget alert;
keep an independently managed account budget if the account will continue to be used.
Local configuration and provider cache are not chargeable; keep state until cleanup is verified.
