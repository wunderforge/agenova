# Filesystem boundary handoff to #48 and #51

Ticket #89 adds one neutral `FilesystemBoundary` value to RuntimeBackend allocation and observation evidence. It does not add a file API, host mount input, or provider type.

| Contract value | Meaning |
| --- | --- |
| `WorkingDirectory` | Backend-selected path visible inside the worker; never a caller-selected host path. |
| `OutsideBoundary` | `RuntimeReadOnlyOtherUnavailable`: runtime files may be read-only; other task data outside the directory is unavailable. |
| `Ephemeral` | Cleanup releases the task directory with no supported workspace retention. |
| `EvidenceLevel` | `Simulated`, `BackendVerified`, or explicit `Unsupported`. |

The in-memory reference reports `/workspace`, the fixed outside rule, ephemeral cleanup, and `Simulated`. Its model cases cover pre-Start denial, task read/write after Start, readable/read-only runtime data, direct outside/traversal denial, fresh replacement, post-termination export denial, and cleanup refusal while termination remains incomplete. A separate trusted local fixture runs real Git and Go commands with an allowlisted credential-free environment; its test collector rejects escape, symbolic link, hard link, special/oversize and collection after explicit collector closure. This proves compatibility only and does not model worker termination.

The current Agent Sandbox adapter reports `Unsupported`. Ticket #48 must map the worker-visible directory, writable/read-only mount layout, HOME/temp/cache placement, and unsupported gaps without changing the shared shape.

Ticket #51 must then run the following as the actual worker identity:

- hold the allocation at Bound and prove a prepared sentinel is untouched until explicit Start (FS-N0);
- run the ordinary repository/test workflow in W (FS-P1);
- attempt a direct absolute-path create/write outside W, plus traversal/alias attempts, and verify outside sentinels remain unchanged (FS-N1/FS-N2);
- start a fresh second claim and prove no first-claim data is visible (FS-N4);
- export one artifact before termination, leave a second sentinel unexported, terminate successfully, and prove post-termination retrieval is denied (FS-N7);
- run a background heartbeat descendant and prove it stops before cleanup can report success; when termination is forced to remain incomplete, cleanup must not report release or reuse (FS-P3/FS-N8);
- record mount/layout and environment evidence showing no unintended host paths, HOME, credential helpers or long-lived provider credentials.

Only that evidence may promote the adapter to `BackendVerified`. Any unsupported Start/termination/filesystem semantic remains a named gap rather than inferred parity.
