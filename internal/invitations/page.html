Access requests

New users sign in with Google. Assign a role before they can access the platform. No invitation email is required.

Policy & Templates

Edit project configuration as JSON. Policy changes require a new metadata.version and become active for new Work. Template changes require a new metadata.name; update Policy rules and select that template when submitting Work. Existing records are never overwritten.

Choose a project and load its current configuration before editing.

Roles & permissions

Platform Admin

Manage users, run Work, read project evidence and manage governance in assigned projects. Deploy and upgrade the serving installation.

Owner and Platform Admins can assign operational roles; Owner remains protected. Deployment also requires AWS/Kubernetes permissions.

Platform Operator

Deploy, upgrade and diagnose the assigned installation using your own cloud identity.

No user management, governance changes, Work submission or business evidence access.

Member

Submit Work using approved templates and read your own results in assigned projects.

No administration, deployment or governance changes.

Owner is the protected account owner, not an assignable role. Changing a role removes incompatible legacy duties. Disabling a user blocks existing sessions. Policy and Template limits still apply to every Work.

Deployment uses the Agenova CLI with separately configured AWS SSO and Kubernetes access. The existing member upgrade supports image-only changes; this page does not upload cloud credentials or edit model configuration.
