Roles & permissions

Fixed roles define what each person can do. Assign roles below; permissions cannot be edited here. Every request is checked by the server.

Account roles

Account Owner

Scope: account

Appoint account and project administrators, manage members, and transfer ownership to an active Account Admin. Submit Work and read evidence across the account.

Does not bypass Work policies or automatically receive infrastructure access.

Account Admin

Scope: account

Manage invitations and ordinary members within authorized projects. Cannot appoint administrators or change ownership. Work access requires a separate project role.

Account Member

Scope: account

Sign in as an invited account member. Work and evidence access require separate project roles. No account administration.

Project roles

Project Admin

Scope: assigned projects

Submit Work and read project evidence. Assign Member or Viewer access in administered projects; only Owner can appoint or remove project administrators.

No Policy, Template, provider credential or cluster management.

Member

Scope: assigned projects

Submit Work using approved templates and requested capabilities. Read your own Work and evidence.

Cannot manage members, change policies or read other members’ Work.

Viewer

Scope: assigned projects

Read project Work and governance evidence.

Cannot submit Work or change members and configuration.

Additional duties

Governance Admin

Scope: account or project

Register immutable Policy versions and compatible AgentTemplates through the authenticated CLI for authorized projects. Policy changes are audited and apply to new Work.

Does not grant Work submission, evidence access or infrastructure permissions.

Platform Operator

Scope: installation

Authorize CLI validation, planning, deployment and status for a named installation. The operator must also supply their own AWS/Kubernetes identity. No cloud credentials are granted by this role.

Does not grant AWS IAM, Kubernetes RBAC, member management or business evidence access.

Account Admin and Project Admin are different

The existing Account Admin role allows invitation and member administration within its checks. It does not grant access to every project. Invitation and member changes require the relevant project administration rights; appointing administrators is reserved for Owner. Assign project roles separately.

Control plane, Gateway, Worker and node identities are service identities, not member roles. A task never inherits its submitter’s administrative duties. Additional roles combine with existing project access; they do not replace it.
